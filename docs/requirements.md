# FitArc — Project Requirements

## 1. Project Overview
FitArc is a mobile workout planner designed to help users organize, manage, and track their workouts.

## 2. Problem Statement
Users may find it difficult to organize workout details and keep track of completed exercises. FitArc aims to provide a simple interface for managing workout plans.

## 3. Project Objectives
- Create and manage workout records.
- Display workout details clearly.
- Search workouts.
- Mark workouts as completed.
- Provide light and dark themes.
- Store workout data locally using Hive CE.

## 4. Functional Requirements
1. The app displays a splash screen.
2. The user can enter the demo login flow.
3. The home screen displays workout information.
4. The user can view the workout library.
5. The user can add a workout with its details.
6. The user can view, edit, and delete workouts.
7. The user can search workouts.
8. The user can mark workouts as completed.
9. The user can change the app theme.
10. The user can access the account screen.

## 5. Workout Data
Each workout contains:
- ID
- Workout name
- Category
- Exercise name
- Sets
- Reps
- Duration
- Date
- Completion status

## 6. Non-Functional Requirements
- Simple and user-friendly interface.
- Responsive mobile layout.
- Reusable Flutter widgets.
- Local data persistence.
- Clear navigation and validation messages.

## 7. Technology Stack
- Design: Figma
- Development: Flutter and Dart
- Local storage: Hive CE
- Version control: Git and GitHub

## 8. Project Limitations
The first version uses demo login and local storage. It does not include real authentication, cloud synchronization, AI features, or multi-user support.

## 9. Development Plan
- Week 1: Documentation, UI/UX design, prototype, and GitHub setup.
- Week 2: Flutter UI, navigation, form validation, and state handling.
- Week 3: Hive CE integration, CRUD operations, and workout search.

## 10. Current Status
Week 1 — Documentation and design phase.
